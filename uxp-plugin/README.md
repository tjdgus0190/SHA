# Luminance Color Picker (UXP Plugin for Photoshop)

TourBox의 휘도 기반 다이내믹 컬러피커와 같은 컨셉:
전경색의 **밝기(휘도)는 고정**한 채, **색상(Hue)·채도(Chroma/Saturation)만 다른
타일 그리드**를 표시하고, 마우스 휠로 색상환을 회전시키며 고르는 플러그인입니다.

## 핵심 알고리즘

- **Lab 모드 (기본)**: sRGB → Linear RGB → XYZ(D65) → CIE Lab 변환 후,
  `L*`을 그대로 고정하고 `a*, b*`만 극좌표(hue, chroma)로 스캔합니다.
  sRGB 색역을 벗어나는 조합은 이진 탐색으로 "해당 hue에서 색역 안에 들어오는
  가장 진한 chroma"를 찾아 표시하므로 타일이 부자연스럽게 깨지지 않습니다.
  (`colorMath.js`의 `generateLabTiles`)
- **Y 모드 (상대휘도)**: WCAG/ITU-R BT.709 공식과 동일한
  `Y = 0.2126·R_lin + 0.7152·G_lin + 0.0722·B_lin` 을 고정합니다.
  HSL 공간에서 Hue/Saturation을 스캔하고, Lightness는 이진 탐색으로
  목표 Y에 맞춥니다. (`generateLumaTiles`)

두 값은 결과가 꽤 다릅니다(Lab L*이 사람 눈에는 더 자연스럽습니다). 패널 상단에서
두 모드를 토글로 전환할 수 있게 해두었습니다.

## 설치 (테스트용)

1. Adobe **UXP Developer Tool**(무료, Adobe 배포)을 설치합니다.
2. UXP Developer Tool에서 "Add Plugin" → 이 폴더의 `manifest.json` 선택.
3. "Load"를 눌러 Photoshop에 플러그인을 로드합니다.
4. Photoshop 메뉴 `Plugins > Luminance Color Picker`에서 패널을 엽니다.

정식 배포하려면 Adobe Developer Console에서 플러그인을 패키징/서명해서
Creative Cloud에 등록해야 합니다(로컬 테스트만 할 거면 이 단계는 필요 없음).

## 단축키 연결 (중요, 그리고 UXP의 한계)

UXP 플러그인은 OS 전역 단축키를 가로챌 수 없습니다. 대신 `manifest.json`에
`command` 타입 entrypoint(`refreshLuminancePicker`)를 등록해 두었는데,
이건 Photoshop 앱 차원의 진짜 단축키로 등록할 수 있습니다:

1. `Edit(Photoshop) > Keyboard Shortcuts and Menus...` (Mac: `Photoshop > Keyboard Shortcuts...`)
2. `Shortcuts For: Plugins` 선택
3. `Luminance Color Picker > Refresh Luminance Tiles (Foreground Color)` 항목을 찾아
   원하는 키(예: `~` 또는 사용하지 않는 F키)를 지정
4. 그림을 그리다가 이 키를 누르면, **패널이 이미 열려 있는 상태**에서
   현재 전경색을 기준으로 타일이 새로고침됩니다.

**한계 (정직하게 말씀드리면)**: UXP는 커서 위치에 붙는 임의의 오버레이 팝업이나,
패널 자체가 자동으로 화면 중앙/커서 근처에 떠오르는 것을 지원하지 않습니다
(패널은 도킹되거나 사용자가 직접 띄운 플로팅 창이어야 함). 그래서 이 구현은
"패널을 화면 한쪽에 작게 띄워두고, 단축키로 그 안의 타일만 갱신"하는 방식입니다.
TourBox 소프트웨어처럼 커서 바로 옆에 진짜 팝업이 뜨는 것과는 다릅니다.
그걸 완전히 재현하려면 CEP(구형, deprecated) + OS 네이티브 오버레이 프로세스를
따로 만드는 방법밖에 없는데, 유지보수성이 매우 나빠서 권장하지 않습니다.

## 조작법

- 패널을 작게(예: 4~5행 × 10~12열) 도킹해두고 그림 그리는 캔버스 옆에 배치
- `Refresh` 버튼 또는 등록한 단축키 → 현재 전경색 기준으로 타일 재생성
- 그리드 위에서 **마우스 휠** → 색상환 회전 (다음/이전 hue 구간 탐색)
- **Shift + 휠** → 채도 범위(Chroma/Saturation 폭) 조정
- 타일 클릭 → 그 색을 전경색으로 적용 (동시에 새 기준색으로 갱신되어 이어서 미세조정 가능)

## 파일 구성

```
manifest.json     UXP 매니페스트 (패널 + 커맨드 entrypoint)
index.html/css    패널 UI
index.js          Photoshop API 연동, 이벤트 처리
colorMath.js       색공간 변환 + 타일 그리드 생성 (순수 함수, 유닛테스트 가능)
icons/             플레이스홀더 아이콘 (교체 권장)
```

## v1.11 변경사항 — "패널을 열어야만 연결됨" 관련 안내 (근본 우회는 불가능)

**질문**: F11 팝업이 메인 사용 방식이 될 텐데, 굳이 Photoshop 안에서
Luminance Picker 패널을 활성화하지 않아도 자동으로 연결될 수 있을까?

**확인한 사실**: UXP 플러그인은 패널을 최소 한 번 열어야 그 안의 JS가
실행되도록 **지연 로딩(lazy load)**됩니다. Adobe 공식 개발자 포럼에도
"매니페스트에 자동 로드/시작 시 활성화 옵션이 있냐"는 질문이 있었는데
(2021년), 그런 옵션은 없습니다. 이건 코드로 우회할 수 있는 버그가
아니라 UXP 플랫폼 자체의 설계라, 완전히 없앨 방법이 없습니다.

**실질적인 우회법 — Photoshop 워크스페이스 활용**: Photoshop은
**워크스페이스** 단위로 어떤 패널이 열려있었는지 기억합니다. 한 번만
설정해두면 매번 수동으로 열 필요가 없어집니다.

1. Luminance Picker 패널을 한 번 엽니다 (`Plugins > Luminance Color Picker`)
2. 패널을 화면 구석에 작게 도킹해둡니다 (거슬리지 않게)
3. `Window > Workspace > New Workspace...`로 지금 상태를 저장합니다
   (또는 기존에 쓰던 워크스페이스에 그냥 덮어써도 됩니다)
4. 그 워크스페이스를 기본으로 쓰면, **Photoshop을 재시작해도 그 패널이
   자동으로 열린 채로 시작**되고, 그 순간 플러그인 JS가 실행되면서
   오버레이 앱과의 연결도 자동으로 이뤄집니다.

즉 "완전히 아무것도 안 해도 연결"까지는 UXP의 근본적인 한계로 불가능하지만,
**워크스페이스에 한 번만 저장해두면 그 이후로는 사실상 자동입니다.**

## v1.10 변경사항 — 오버레이 앱 연결 실패 시 조용히 죽던 버그 수정 + 로그 강화

**발견한 버그**: `connectOverlayApp()`에서 `new WebSocket(...)` 생성 자체가
실패하면(예: 그 순간 네트워크 권한이 제대로 안 걸렸거나 하는 일시적 문제),
**재시도 스케줄조차 걸리지 않고 그냥 영원히 포기**했습니다. 로그도 전혀
안 남아서 사용자 입장에선 원인을 알 방법이 없었습니다.

**수정**: 생성 실패도 `close` 이벤트와 동일하게 재시도를 예약하도록
바꿨고, 연결 성공/실패/메시지 수신/에러 각 단계마다 명확한 로그를
추가했습니다. 이제 Photoshop 콘솔(플러그인 `•••` 메뉴 → Inspect)에서
`[LuminancePicker] 오버레이 앱에 연결됨` 로그가 뜨는지 직접 확인할 수
있습니다.

**현재 상태**: "모든 모드에서 양방향으로 안 된다"는 증상은 두 앱
사이의 연결 자체가 문제일 가능성이 가장 큽니다. 코드 자체(WS 프로토콜,
`pickColorFromRgb`, `sendForegroundToOverlay` 등)는 다시 봐도 로직상
문제를 못 찾았어서, 이번엔 **양쪽 콘솔 로그로 정확히 어디서 끊기는지
확인하는 게 먼저**입니다:

1. 오버레이 앱을 실행한 터미널에서 `[overlay] UXP plugin connected`가 뜨는지
2. Photoshop 콘솔(Inspect)에서 `[LuminancePicker] 오버레이 앱에 연결됨`이 뜨는지

둘 다 뜬다면 연결 자체는 됐다는 뜻이니, 그 다음엔 타일을 클릭했을 때
`[overlay] UXP plugin connected` 근처에 다른 로그가 더 뜨는지(타일 클릭 시
overlay 쪽에서 뭔가 로그가 나가는지) 확인이 필요합니다.

## v1.9.0 변경사항 — 필드가 계속 까맣게 보이던 진짜 원인 발견 (createImageData 미지원)

패널에 에러 배너를 추가하고 나서야 정확한 원인이 드러났습니다:

```
TypeError: fieldCtx.createImageData is not a function
```

**Photoshop UXP의 캔버스 2D 구현이 `createImageData`/`putImageData`(픽셀
단위 조작 API)를 지원하지 않습니다.** v1.5.0에서 비정형 블롭 필드를
"캔버스 픽셀 하나하나를 계산해서 그리는" 방식으로 만들었는데, 이 API
자체가 UXP 환경에 없어서 매번 렌더링을 시도할 때마다 조용히(에러 배너가
없던 그때는) 실패하고 있었던 것입니다. 그래서 필드는 계속 비어있고,
렌더링 함수가 예외로 중단되면서 hex/명도 그래프/스와치까지 전부 그
직전 상태(HTML 초기 placeholder)에 멈춰 있었던 것 — "스포이드를 찍어도
전혀 안 바뀐다"는 증상과 정확히 일치합니다.

**수정**: 모든 캔버스 구현이 기본으로 지원하는 `fillRect`로 바꿨습니다.
픽셀 하나하나 대신 3px 크기의 작은 타일을 촘촘히 채워 그리는 방식으로,
완전한 픽셀 단위보다는 살짝 거칠지만 비정형 블롭의 모양과 색은 동일하게
나옵니다.

**검증**: `createImageData`/`putImageData`를 아예 제거한 (실제 UXP와
동일한) 환경을 Node로 재현해서, 에러 없이 정상 렌더링되는 것과
`fillRect`가 실제로 수백~수천 번 호출되는 것을 확인했습니다.

### 이번 일에서 얻은 교훈 (앞으로도 적용)

이 버그는 "실제 Photoshop 없이 만든 코드가 UXP 환경의 API 제약과 충돌"한
사례입니다. 앞으로 캔버스/DOM API를 새로 쓸 때는 최대한 기본적인 API
(fillRect, arc, path 등)로 제한하고, 픽셀 버퍼 조작처럼 지원 여부가
불확실한 API는 피하겠습니다. 그리고 이번에 추가한 **패널 안 에러 배너**
(다른 상태 메시지에 안 밀리고 지속되는) 덕분에 이런 문제를 다음부터는
훨씬 빨리 찾을 수 있을 것입니다.

## v1.8.0 변경사항 — "스포이드 찍어도 팔레트가 안 움직임" 버그 수정

**증상**: 패널이 열리면 Photoshop 기본 전경색(검정, `#000000`)이 뜨는데,
스포이드로 색을 추출해도 팔레트/명도 그래프가 계속 `#000000`에 고정된 채
전혀 안 움직임.

**원인**: v1.3.0에서 만든 자동 갱신 리스너가 `action.addNotificationListener`
로 전경색 변경 이벤트를 감지하려 했는데, 그 이벤트의 정확한 디스크립터
구조(`_target`의 `_property`/`_ref` 값 등)를 **실제 Photoshop 없이 추측으로
작성**했습니다. 실제 스포이드가 발생시키는 이벤트 구조가 그 추측과 다르면
필터 조건에 안 걸려서 리스너가 그냥 무시됩니다 — 정확히 이 증상과 일치.

**수정**: 이벤트 구조를 추측하는 방식을 버리고, **500ms마다 실제 전경색을
직접 읽어서 이전 값과 다르면만 재렌더링**하는 폴링 방식으로 바꿨습니다.
이벤트가 어떤 모양으로 오든(또는 아예 안 오든) 상관없이 최대 0.5초 안에
반드시 반영됩니다. 값이 안 바뀐 경우엔 재렌더링을 생략하므로 폴링 자체의
비용은 거의 없습니다 (3개 숫자 비교뿐).

**검증**: 알림 리스너가 전혀 발동하지 않는 최악의 상황을 스텁으로 그대로
재현해서, 폴링만으로 `#000000 → #e63cb4`로 정확히 갱신되는 것을
확인했습니다.

## v1.5.0 변경사항 — TourBox 스크린샷 분석 반영한 UI 전면 재설계

### 비정형 블롭 필드로 교체

기존 원형 타일 링을 없애고, 스크린샷에서 본 것과 동일한 **비정형 색상 필드**로
바꿨습니다. 이 울퉁불퉁한 모양은 디자인이 아니라 **특정 밝기(L*)에서 sRGB가
실제로 표현 가능한 색의 진짜 경계**입니다 — `labToRgb()`의 in-gamut 체크를
캔버스 픽셀 단위(240×200)로 그대로 그려서 만들었습니다. hue별 최대 채도가
34~111까지 들쭉날쭉하다는 걸 직접 계산해서 확인했고(L*=60 기준), 그 결과가
정확히 이 블롭 모양을 만듭니다. 필드 안에서 드래그하면 색상(hue)과
채도(chroma)를 동시에 고를 수 있고, 커서는 항상 지금 선택된 색 위치에 있습니다.

### 명도 슬라이더 (드래그 가능)

하단 가로 슬라이더로 L*(또는 Y)를 직접 드래그해서 바꿀 수 있습니다. 바꾸면
필드 전체가 그 밝기 기준으로 다시 계산되어 다른 모양의 블롭이 나타납니다.

### 스포이드 자동 연동

상단 스포이드 아이콘(또는 배정한 단축키 → `activateEyedropper` 커맨드)을 누르면
`batchPlay`로 Photoshop의 실제 스포이드 도구로 전환됩니다
(`{_obj:"select", _target:[{_ref:"eyedropperTool"}]}`). 이후 캔버스를 클릭해
색을 추출하면, 기존에 구현해둔 자동갱신 리스너가 그 변경을 감지해서

## v1.3.0 변경사항

### "펜 촉을 따라다니는 패널" — 다시 한번 명확히: UXP에서 불가능합니다

이건 "필수"라고 요청하셔도 우회할 방법이 없습니다. UXP는 (1) 캔버스 위
마우스/펜 좌표를 가져오는 API가 없고, (2) 패널을 특정 화면 좌표에
프로그래밍적으로 띄우는 API도 없습니다. Adobe 공식 개발자 포럼에도 각각
별개의 미해결 기능요청으로 남아있습니다. 이건 이 플러그인 설계의 문제가
아니라, UXP 플랫폼 자체의 하드 리밋입니다. 정말 이 기능이 꼭 필요하다면
남는 방법은 Photoshop 플러그인이 아닌 **완전히 별도의 OS 레벨 오버레이
프로그램**(TourBox 자체 소프트웨어와 같은 방식)을 만드는 것뿐이고, 이는
UXP 플러그인과는 아예 다른 프로젝트입니다.

### 대신 구현한 것: "찍으면 자동 반영"

Photoshop 스포이드 도구(`I` 키, 또는 브러시 사용 중 `Alt`/`Option` 임시 전환)로
캔버스의 한 점을 찍으면 Photoshop이 전경색을 바꾸는데, 그 변경을
`action.addNotificationListener`로 감지해서 **버튼도 단축키도 없이 그 즉시**
팔레트(링/히스토리/명도 그래프)가 새로 계산됩니다. 실제 동작을 스텁 환경에서
검증: 스포이드로 완전히 다른 색을 찍는 것을 시뮬레이션했을 때 자동으로
`#3a7bd5 → #28140a`처럼 팔레트 기준색이 갱신됨을 확인했습니다.

- 이 자동갱신은 **외부에서** 전경색이 바뀔 때만 발동합니다. 플러그인 스스로
  hue/chroma 단축키로 전경색을 바꿀 때는 알림을 잠깐 억제해서(60ms), 무한
  루프나 "매번 정수 RGB로 반올림되며 L*이 미세하게 계속 틀어지는" 오차 누적을
  막았습니다.
- `addNotificationListener`가 없는 구버전/환경에서도 기존의 수동 새로고침
  (`refreshLuminancePicker` 커맨드, 패널의 ⟳ 버튼)은 항상 동작합니다.

### 명도(0~100) 그래프

패널 하단에 검정→흰색 그라데이션 막대와 마커로 현재 기준색의 밝기
(Lab 모드는 L*, 상대휘도 모드는 Y×100)를 0~100 스케일로 표시합니다.

**중요한 시각적 특성**: hue/chroma 단축키로 색상환을 아무리 돌려도 이
마커는 **전혀 움직이지 않습니다** — 그게 "동명도 유지"가 실제로 지켜지고
있다는 증거입니다. 마커가 움직이는 건 스포이드로 진짜 다른 밝기의 색을
새로 찍었을 때뿐입니다. (스텁 테스트로 hue step 전후 마커 위치가 완전히
동일함을 확인함)

## v1.2.0 변경사항 — 휠 대신 키보드 단축키로 (포커스 문제 해결)

**문제**: 그림을 그리다가 패널 위로 마우스를 옮기지 않고 캔버스/레이어 패널에
포커스가 있는 채로 휠을 굴리면, 그 포커스가 있는 곳(레이어 목록 스크롤 등)이
반응해버리고 정작 색은 안 바뀝니다. UXP는 캔버스 위 마우스/휠 이벤트를 가로챌
API가 아예 없어서 ("Alt+휠"처럼 모디파이어+휠 조합을 캔버스 위에서 감지하는
것도 포함) 이 문제를 UXP 안에서 근본적으로 해결할 방법이 없습니다.

**해결**: 휠 하나 대신, **Photoshop 자체의 키보드 단축키**로 여러 개의
"커맨드"를 등록했습니다. 이건 포커스가 어디에 있든 항상 작동하는 진짜
Photoshop 단축키라서, 그림 그리다가 그대로 눌러도 100% 반응합니다.

### 새로 추가된 커맨드 (Edit > Keyboard Shortcuts > Plugins 에서 배정)

| 커맨드 | 기본 동작 | 추천 단축키 예시 |
|---|---|---|
| Hue + (Small Step) | 색상환 +15° | `]` |
| Hue - (Small Step) | 색상환 -15° | `[` |
| Hue + (Big Step) | 색상환 +60° | `Shift+]` |
| Hue - (Big Step) | 색상환 -60° | `Shift+[` |
| Saturation Range + | 채도 범위 확대 | `Ctrl/Cmd+]` |
| Saturation Range - | 채도 범위 축소 | `Ctrl/Cmd+[` |
| Jump to Complementary Hue | 보색(180°)으로 즉시 점프 | `\` (백슬래시) |
| Refresh From Foreground | 지금 전경색 기준으로 리셋 | 원하는 키 |

`]`/`[` 를 쓴 이유는 브러시 크기 조절과 같은 손 위치라 손이 브러시-사이즈
단축키와 색상 단축키 사이를 오갈 필요가 없기 때문입니다. 원하는 키로
자유롭게 바꾸셔도 됩니다.

### 연타/길게 누르기 대응

키를 연달아 누르거나 OS 자동반복으로 빠르게 여러 번 눌려도, 내부적으로
90ms 디바운스가 걸려서 **마지막 상태만 실제로 Photoshop 전경색에 커밋**됩니다.
Undo 히스토리가 키 입력 횟수만큼 쌓이지 않습니다. (스텁 테스트로 3연타 →
실제 커밋 1회만 발생하는 것 확인함)

### 동명도 팔레트 기능 고도화

- **보색 점프**: 그림자/하이라이트에 자주 쓰는 "같은 밝기의 반대 색상"으로
  한 번에 이동하는 전용 커맨드 추가.
- **큰 스텝 / 작은 스텝 분리**: 미세 조정용 15°와 빠른 탐색용 60°를 별도
  커맨드로 분리해서, 원하는 정밀도로 바로 이동 가능.
- **최근 색 히스토리**: 패널 하단에 최근 적용한 색이 스와치로 쌓입니다.
  이전에 쓰던 동명도 색으로 클릭 한 번에 복귀할 수 있습니다 (패널이 열려
  있을 때만 보이는 보조 기능이며, 키보드 커맨드 자체는 패널이 닫혀 있어도
  동작합니다 — 색 계산/커밋 로직이 DOM 렌더링과 분리되어 있음).
- 패널 위에 마우스가 실제로 있을 때는 예전처럼 휠/Shift+휠도 계속 동작합니다
  (보조 수단으로 남겨둠).

## v1.1.0 변경사항 — "흐름이 안 끊기게" 목표에 맞춘 개편

**커서 위치에 뜨는 팝업은 UXP에서 근본적으로 불가능합니다.** UXP는

대신 이번 버전은 실제로 가능한 범위에서 "흐름 방해 최소화"를 노렸습니다:

- **사각 그리드 → 원형 링 하나로 축소**: 여러 행을 스캔할 필요 없이,

- 타일 클릭은 여전히 즉시 커밋됩니다 (디바운스 없음).

### 그래도 남아있는 한계

## v1.0.1 변경사항

- **DOM 초기화 버그 수정**: `manifest.json`의 `main`이 `index.html` 하나이므로
  패널과 커맨드(단축키)는 같은 페이지 컨텍스트를 공유합니다. 이전 버전은
  DOM 캐싱을 패널이 열릴 때(`panel.show()`)만 했기 때문에, 패널을 한 번도
  열지 않고 단축키부터 누르면 아무 반응이 없었습니다. 지금은
  `DOMContentLoaded` 시점에 한 번만 초기화하고, 그 이전에 커맨드가 호출되면
  `pendingRefresh` 플래그로 큐잉해서 초기화 직후 반영합니다.
- **전경색 읽기/쓰기에 폴백 추가**: `app.foregroundColor.rgb.red` 접근이
  실패하면 `hexValue` 파싱으로, `batchPlay` set이 실패하면 `SolidColor`
  객체 대입 방식으로 재시도합니다. 둘 다 실패하면 조용히 무시하지 않고
  패널 하단에 에러 메시지를 표시합니다(`#statusMsg`).
- **동적 chroma 범위 (L=10, 95 같은 극단값 테스트 완료)**: 고정
  `maxChroma=90` 대신, hue마다 `findMaxChromaForHue()`로 실제 sRGB
  색역에서 도달 가능한 최대 chroma를 이진 탐색으로 구하고 그 비율로
  행을 나눕니다. 매우 어둡거나(L*≈10) 매우 밝은(L*≈95) 색에서도 타일이
  전부 회색으로 뭉개지지 않고 hue별 차이가 드러납니다. `Shift+휠`로
  조정하는 `chromaScale`은 이제 이 hue별 최대치에 대한 배율로 작동합니다.
- **휠 이벤트 rAF 쓰로틀링**: 빠르게 휠을 굴려도 프레임마다 한 번만
  그리드를 재계산하도록 개선.
