# docs/ad-video — SHA Paint 15초 광고

실제 Photoshop 녹화 없이 코드로 만든 모션그래픽 버전이다. 팝업 필드·명도 바는 앱의 실제 색 계산 파일(`app/colorMath.js`)로 그리고, 팝업 레이아웃은 `app/overlay.html`·`overlay.css`(v8.7 커밋 기준)를 옮겨 왔다. 화면 속 "드로잉 앱"은 연출용 목업이라 영상 하단에 "연출 화면" 표기를 넣었다.

## 파일
| 파일 | 내용 |
|---|---|
| `sha-paint-ad-15s-9x16.mp4` | 메인. 1080x1920, 30fps, 15.00s(450프레임), H.264 + AAC 효과음 |
| `sha-paint-ad-15s-16x9.mp4` | 가로 변형. 1920x1080, 그 외 동일 |
| `ad.html` | 영상 원본. 브라우저로 열면 반복 재생된다(스페이스 = 일시정지, ←/→ = 0.5초 이동). `?ar=16x9`, `?cta=…`, `?url=…` 파라미터 |
| `script.md` | 컷별 스크립트(타임코드/화면/자막/내레이션/SFX), 16:9 메모, 기능 근거 표 |
| `storyboard.md` | 컷별 구도, 레이아웃 좌표, 확인용 프레임 목록 |
| `render/render.js` | 프레임 단위 캡처 → ffmpeg로 MP4 만드는 스크립트 |
| `render/sfx.js` | 효과음 합성(수식으로 생성, 외부 음원 없음) |
| `frames/` | 검증용 프레임(MP4에서 직접 뽑은 1/5/10/14초 PNG, 0.5초 간격 썸네일 모음) |

## 다시 렌더링하기 (Windows)
프로젝트 `package.json`을 건드리지 않도록 의존성은 프로젝트 밖 작업 폴더에 설치한다.
```powershell
mkdir C:\temp\ad-render; cd C:\temp\ad-render
npm init -y; npm i puppeteer-core ffmpeg-static
$env:AD_RENDER_DEPS = "C:\temp\ad-render"
cd "D:\SHA PAINT\docs\ad-video"
node render\render.js --ar 9x16          # → sha-paint-ad-15s-9x16.mp4  (약 1분)
node render\render.js --ar 16x9          # → sha-paint-ad-15s-16x9.mp4
node render\render.js --ar 9x16 --stills 1,5,10,14   # 확인용 PNG만 (frames/)
```
옵션: `--cta "지금 체험하기"`, `--url "shapaint.com"`(엔드카드 문구), `--no-audio`, `--fps 60`, `--chrome <chrome.exe 경로>`(기본 `C:\Program Files\Google\Chrome\Application\chrome.exe`).
- 시간은 `window.renderAt(t)`로 프레임마다 직접 정한다(결정적). 실시간 녹화가 아니라 끊김이 없다.
- 폰트: Windows에 설치된 Noto Sans KR / Noto Serif를 쓴다(없으면 맑은 고딕으로 대체되어 자막 폭이 달라질 수 있으니 `--stills`로 먼저 확인).
- 렌더 중 `render/sfx-<비율>.wav`가 만들어진다(중간 파일, 지워도 됨).
- 타이밍·자막을 고칠 곳: `ad.html`의 `CAPTIONS`, `buildTimeline()`. 효과음 큐도 같은 함수에서 나온다.

## 음원
- 영상에 든 소리는 `render/sfx.js`가 수식으로 만든 효과음(휙, 클릭, 팝, 틱, 칠하는 소리, 지우개, 차임)뿐이다. 외부 음원을 쓰지 않아 저작권 문제가 없다.
- **배경음악은 넣지 않았다.** 넣는다면 저작권 프리만 쓴다:
  - YouTube 오디오 보관함(YouTube 업로드 한정, 곡마다 저작자 표시 조건 확인), 인스타그램/틱톡 앱 내 상업용 라이브러리(Business 계정은 "상업용 음원"만 가능)
  - 구독형 라이선스(Artlist, Epidemic Sound 등)는 광고 집행 범위가 라이선스에 포함되는지 확인
  - 분위기: 차분한 로파이/어쿠스틱, 100~115 BPM. 5.1초(팝업 등장)에 비트가 들어오게 맞추면 좋다. 효과음과 겹치니 음악은 -18 dB 안팎으로 낮게.
- 내레이션 초안은 `script.md`에 있다(영상에는 없음).

## 실제 화면 녹화로 교체할 컷 (실기 촬영 가이드)
코드 버전은 "어떻게 동작하는지"를 보여주는 재현이다. 판매 신뢰도를 위해 아래 컷은 사용자 PC에서 실제 화면으로 바꾸는 것을 권한다. 이 작업은 샌드박스에서 할 수 없다(Photoshop + 와콤 + 화면 녹화 필요).

| 우선순위 | 컷 | 실기 녹화 내용 | 자막 |
|---|---|---|---|
| 1 | 컷 3–4 (5.0–10.4s) | 펜 사이드 버튼(중클릭 매핑) → 펜 옆에 팝업 → 필드 드래그 → 브러시 색 바뀌고 바로 칠하기, 2~3회 | 그대로 |
| 2 | 컷 6 (11.6–13.4s) | 팝업 히스토리 스와치 클릭 → 브러시 색 재적용 → 칠하기 | 그대로 |
| 3 | 컷 1–2 (0–5.0s) | Photoshop 기본 색상 피커/색상 패널을 오가며 고르고, 테스트 칠 → 지우개 | 그대로 |
| 4 | 컷 5 (10.4–11.6s) | Photoshop에서 흑백 확인(예: 맨 위에 채도 0 조정 레이어 또는 "보기 > 교정 설정 > 사용자 정의"의 회색조) — 코드 버전처럼 L* 정확 변환은 아니므로 "비슷하게 보이는 것"만 쓰고, 정확한 비교가 필요하면 지금의 코드 컷을 유지 | 그대로 |
| — | 컷 7 엔드카드 | 교체 불필요(코드 버전 사용) | — |

### 촬영 체크리스트
- [ ] 화면 녹화: OBS Studio(무료). 9:16용으로 캔버스 영역을 세로로 크롭할 수 있게 **2560x1440 이상, 60fps**로 녹화. 출력 30fps로 맞춘다.
- [ ] Windows 디스플레이 배율 100~150%, Photoshop UI 크기 "크게" — 폰에서 팝업이 보이도록.
- [ ] **커서가 녹화에 찍히는지** 확인(OBS "커서 캡처" 켜기). 와콤 펜은 마우스 이벤트가 없어 커서 표시가 다를 수 있으니 시험 녹화 필수. 안 찍히면 편집에서 커서 오버레이를 추가.
- [ ] 와콤 펜 사이드 버튼을 "가운데 클릭"으로 매핑(Wacom 데스크톱 센터). 트리거를 바꿨다면 영상의 "중클릭" 칩 문구도 맞게 수정.
- [ ] SHA Paint 상태 패널이 활성(ON)인지, 팝업이 잘 뜨는지 녹화 전 리허설.
- [ ] 히스토리를 비우고 시작하거나, 보여주고 싶은 색 4~5개만 미리 쌓아 둔다(앱을 껐다 켜면 히스토리가 남아 있을 수 있음).
- [ ] 캔버스: 단순한 선화(꽃, 캐릭터 얼굴 등) + 흰 배경. 브러시는 크고 단단한 원형.
- [ ] 예시 색은 같은 L*에서 고른다 — 기준색 하나를 스포이드로 찍고 팝업에서만 색을 바꾸면 자동으로 그렇게 된다.
- [ ] **녹화 중 검정 글리치가 보이면 그 테이크는 버린다**(알려진 미해결 이슈, CLAUDE.md "핵심 문제"). "색 적용 실패" 배너가 뜬 테이크도 버린다.
- [ ] 알림·작업표시줄·개인 파일명이 화면에 나오지 않게(방해 금지 모드, 파일명 `illust_01` 등).
- [ ] 사용한 Photoshop/OS 버전을 기록(광고 문구 "Windows 10/11"과 실제 테스트 환경이 맞는지 확인용).
- [ ] 촬영본 편집 시 자막·엔드카드는 `ad.html`과 같은 문구/색(#e8a33d)을 쓴다. 엔드카드는 `--stills 14.5`로 PNG를 뽑거나 MP4의 13.4–15.0s 구간을 그대로 이어붙인다.

## 확정이 필요한 것
- CTA 문구: 체험판이 실제로 있는지 미확정이라 기본값을 "지금 만나보기"로 두었다(요청안은 "지금 체험"). 확정되면 `--cta`로 재렌더.
- 랜딩/판매 URL: 아직 없음(`site/index.html`의 Gumroad 링크가 플레이스홀더). 영상은 "링크는 프로필에서 / 설명란에서"로 대신했다.
- 가격: `docs/pricing.md`가 아직 없어서 영상에 가격을 넣지 않았다.

## v3 — 인스타 릴스/스토리용 15초 (9:16, 메인 기능 중심)
- `v3/sha-paint-ad-v3-15s-9x16.mp4` (한국어), `v3/sha-paint-ad-v3-15s-9x16-en.mp4` (영문) — 1080×1920, 30fps, 15.00s, 효과음 포함
- 메시지: "펜 옆 팔레트"가 아니라 **명도(L*) 고정 → 지금 색과 같은 명도에서 어울리는 색 → 입체감(명암)이 안 무너짐**이 주인공
  | 구간 | 화면 | 자막 |
  |---|---|---|
  | 0–3.8s | 보통 피커로 구의 기본색을 노랑/파랑으로 → 흑백 미리보기에서 명암 뒤집힘, L* 65→87/36 빨간 표시 | 색만 바꿨을 뿐인데 / 입체감이 무너졌다? |
  | 3.8–6.4s | SHA Paint 팝업, 명도 바 핸들에 잠금 아이콘, "명도 잠금 · L* 65" | SHA Paint는 / 명도를 고정합니다 |
  | 6.4–9.6s | 같은 명도 필드에서 색을 훑음(코랄→노랑→초록→청록→로즈) — 흑백 미리보기는 그대로, "명암 유지" | 지금 색과 같은 명도에서 / 어울리는 색을 바로 |
  | 9.6–12.4s | 그림자(L*40)·빛(L*85) 색도 바꿈 → 화면 전체 흑백 전환해도 처음과 같은 명암 | 그림자·빛 색까지 바꿔도 / 입체감은 그대로 |
  | 12.4–15s | 엔드카드: 새 팔레트 구 + 흑백 구, "명도는 고정, 색만 자유롭게", $10 · 1회 결제, CTA | — |
- 릴스 하단 UI(약 아래 20%)와 겹치지 않게 핵심 요소는 y 1650 위에 배치.
- 원본 `v3/ad-v3.html`(문구는 상단 `T`, 팔레트는 `START`/`H_*_END`), 렌더 `node v3/render-v3.js [--lang en] [--stills 1,5,8,11,14]`
- 폰트가 설치되지 않은 PC/Linux: `AD_RENDER_DEPS` 폴더에 `npm i @fontsource/noto-sans-kr @fontsource/noto-serif`를 같이 설치하면 렌더 스크립트가 자동 주입. `CHROME_PATH`, `FFMPEG` 환경변수로 실행 파일 지정 가능.
- 구·필드 색은 전부 `app/colorMath.js`로 계산(흑백 = 같은 L*의 회색). 구는 셀 셰이딩 연출이며 화면 하단에 "연출 화면" 표기.
